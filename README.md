# depgraph - граф зависимостей пакетов Alpine Linux

Консольный инструмент визуализации графа зависимостей для менеджера
пакетов Alpine Linux (формат apk). Вариант №6, практическая работа №2
по дисциплине «Конфигурационное управление».

Готовые менеджеры пакетов и сторонние библиотеки для получения
зависимостей не используются: только стандартная библиотека Python 3.

## Состояние проекта

Реализованы все этапы (1-5): чтение конфигурации из YAML, получение
зависимостей из репозитория apk, построение графа зависимостей
(с учётом транзитивности и циклов), тестовый режим, вывод обратных
зависимостей и визуализация графа на языке D2 с сохранением в SVG.

## Настройки

Все параметры задаются в YAML-файле (по умолчанию `config.yaml`).

| Параметр      | Описание                                                  |
|---------------|-----------------------------------------------------------|
| `package`     | Имя анализируемого пакета                                 |
| `repository`  | URL репозитория или путь к файлу тестового репозитория    |
| `test_mode`   | `true` - тестовый репозиторий из файла, `false` - реальный |
| `version`     | Версия пакета                                             |
| `output_file` | Имя файла с изображением графа (расширение `.svg`)       |

Поддерживается плоский YAML: строки `ключ: значение`, комментарии `#`,
значения можно брать в кавычки.

Проверки: заданы все параметры и нет лишних; в тестовом режиме имя
пакета состоит из больших латинских букв, а файл репозитория существует;
в обычном режиме `repository` - URL (`http://`, `https://`, `file://`);
версия начинается с цифры; `output_file` оканчивается на `.svg`, папка
для него существует.

## Как получаются зависимости (этап 2)

Репозиторий Alpine содержит файл `APKINDEX.tar.gz`. Приложение скачивает
его по адресу `<repository>/APKINDEX.tar.gz` (`urllib`), распаковывает
(`tarfile`) и разбирает текстовый индекс: записи разделены пустой
строкой, поля имеют вид `P:` (имя), `V:` (версия), `D:` (зависимости),
`p:` (предоставляемые имена).

* Ищется запись пакета `package` с версией `version`. Если версии нет,
  в сообщении об ошибке перечисляются доступные версии.
* Записи зависимостей (`D:`) очищаются от ограничений версий
  (`>=`, `=`, `<`, `~`); конфликты (`!имя`) зависимостями не считаются.
* Виртуальные имена (`so:libc.musl-x86_64.so.1`, `cmd:sh`, `pc:...`)
  заменяются именем пакета, который их предоставляет (поле `p:`).
  Если поставщиков несколько, берётся первый в индексе.
* Имя, которое не удалось сопоставить (например, зависимость из другого
  репозитория, не загруженного в индекс), выводится как есть.
* Зависимость пакета от самого себя игнорируется.

В обычном режиме `repository` - это адрес каталога с индексом, например
`https://dl-cdn.alpinelinux.org/alpine/v3.20/main/x86_64`. Допустим и
адрес `file://`.

## Граф зависимостей (этап 3)

Граф строится обходом в глубину (DFS) **без рекурсии**: используется
явный стек пар «вершина - итератор по её зависимостям», поэтому глубина
графа не ограничена лимитом рекурсии Python.

* Каждая вершина раскрывается один раз (общие зависимости не
  дублируются), вершины хранятся в порядке обнаружения.
* Циклы: если зависимость уже лежит на текущем пути обхода, ребро
  сохраняется в графе, цикл записывается в список циклов, но вершина
  повторно не раскрывается - обход всегда завершается. Самозависимость
  (`F: F`) тоже считается циклом.
* Вывод: строки вида `A -> B, C`, затем (если есть) список циклов.

### Тестовый режим

При `test_mode: true` параметр `repository` - путь к файлу описания
графа. Пакеты называются большими латинскими буквами, каждая строка -
`пакет: зависимости через пробел`. Пустой список означает отсутствие
зависимостей, пакет, не описанный отдельной строкой, считается листом.
Допускаются пустые строки и комментарии `#`. Версия в тестовом режиме
при поиске не используется. Корневой пакет должен быть описан в файле.

```
# пример: examples/repo_cycle.txt
A: B
B: C
C: A D
D:
```

Готовые примеры: `examples/repo_simple.txt`, `examples/repo_cycle.txt`,
`examples/repo_complex.txt` и конфигурации `examples/config_*.yaml`.

## Обратные зависимости (этап 4)

Режим включается ключом `--reverse`. Обратные зависимости пакета - это
пакеты, которые зависят от него (прямо или через цепочку других пакетов).

1. У всех пакетов репозитория берутся прямые зависимости, и рёбра
   разворачиваются: если `B` зависит от `D`, появляется ребро `D -> B`.
2. На получившемся графе запускается **тот же** итеративный DFS
   (`build_graph`) из пакета `package`.
3. Вершины, достигнутые обходом, - это все пакеты, зависящие от
   `package`; потомки корня - те, кто зависит от него напрямую.

В обычном режиме для этого используется весь загруженный индекс
(`APKINDEX` репозитория), поэтому учитываются только пакеты того
репозитория, который указан в `repository`. Циклы выводятся в
направлении «зависит от»: `D -> G -> H -> D` означает, что `D` зависит
от `G`, `G` - от `H`, `H` - от `D`.

## Визуализация (этап 5)

Для графа формируется описание на языке диаграмм **D2** и изображение
в формате **SVG**. Оба файла создаются рядом: имя SVG берётся из
параметра `output_file`, D2-описание сохраняется под тем же именем с
расширением `.d2` (`graph.svg` -> `graph.d2`).

* Все имена в D2 берутся в двойные кавычки (имена пакетов содержат
  точки, плюсы и двоеточия, которые в D2 имеют особый смысл).
* Корневой пакет подсвечен жёлтым, рёбра, замыкающие циклы, - красным
  пунктиром.
* Если в системе установлена утилита [d2](https://d2lang.com) (команда
  `d2` доступна в `PATH`), SVG строит она: `d2 graph.d2 graph.svg`.
  Если утилиты нет или она завершилась с ошибкой, используется
  встроенная отрисовка (`src/svg_render.py`): вершины раскладываются по
  колонкам-уровням (расстояние от корня), рёбра - кривые со стрелками.
  Внешний вид изображений в двух случаях разный, содержимое графа - то же.
  В строке `Изображение (SVG, ...)` в консоли указано, чем нарисован SVG.

Примеры D2-описания и изображений (тестовые репозитории) лежат в
`examples/images/`: `simple`, `cycle`, `complex`.

```
# examples/images/cycle.d2
direction: right

"A": {
  style: {
    fill: "#ffe699"
  }
}
"B"
"C"
"D"

"A" -> "B"
"B" -> "C"
"C" -> "A": {
  style: {
    stroke: "#cc0000"
    stroke-dash: 3
  }
}
"C" -> "D"
```

### Сравнение со штатным инструментом apk

Штатное средство визуализации зависимостей apk - команда `apk dot`,
которая выводит граф в формате Graphviz DOT. Для сравнения на Alpine
(или в контейнере `alpine`) для пакета `P` выполните:

```
apk update
apk add graphviz
apk dot P | dot -Tsvg -o P_apk.svg
```

и постройте граф этим приложением с теми же `repository` и `version`.
Сравнивать нужно множество вершин и рёбер. Возможные причины
расхождений:

* `apk dot` использует собственный алгоритм выбора пакетов-поставщиков
  и учитывает ограничения версий, а здесь для виртуального имени
  (`so:`, `cmd:`, `pc:`) берётся первый поставщик в индексе;
* `apk dot` работает со всеми репозиториями из `/etc/apk/repositories`
  (`main`, `community`), а приложение - с одним указанным; зависимости
  из других репозиториев остаются в графе неразрешёнными именами;
* `apk dot` по умолчанию берёт актуальную версию пакета, а здесь версия
  задана параметром `version`;
* конфликты (`!имя`) в графе не рисуются.

Результаты сравнения для трёх выбранных пакетов нужно получить на
своей машине: в этом репозитории они не зафиксированы.

## Структура репозитория

```
src/
  main.py        точка входа, режимы работы
  config.py      YAML-конфигурация и её проверка
  apk_index.py   загрузка и разбор APKINDEX
  repo.py        источники данных (тестовый и apk)
  file_repo.py   разбор файла тестового репозитория
  sources.py     выбор источника по настройкам
  graph.py       итеративный DFS, циклы
  reverse.py     обратные зависимости
  d2.py          описание графа на языке D2
  svg_render.py  встроенная отрисовка SVG
  render.py      сохранение D2 и SVG
tests/           модульные тесты (unittest)
examples/        тестовые репозитории, конфигурации, изображения
```

## Запуск

```
run.bat [config.yaml] [--reverse]        (Windows)
./run.sh [config.yaml] [--reverse]       (Linux/macOS)
python -m src.main [config.yaml] [--reverse]
```

Без `--reverse` строится и выводится граф зависимостей пакета, с
`--reverse` - список пакетов, которые зависят от него.

Требуется Python 3.9 или новее.

## Тесты

```
python -m unittest discover -s tests -t .
```

## Примеры

Конфигурация (`config.yaml` из репозитория) для реального репозитория:

```
package: nginx
repository: https://dl-cdn.alpinelinux.org/alpine/v3.20/main/x86_64
test_mode: false
version: 1.26.2-r0
output_file: graph.svg
```

Граф пакета из локального тестового индекса (`tests/apk_fixture.py`,
репозиторий задан адресом `file://`):

```
$ python -m src.main local.yaml
Граф зависимостей пакета app:
  app -> lib, musl, tool
  lib -> musl
  musl (нет зависимостей)
  tool (нет зависимостей)
```

Неверная версия или недоступный репозиторий:

```
$ python -m src.main local.yaml
Ошибка: пакет 'app': версии '9.9' нет (доступны: 1.0-r0, 0.9-r0)

$ python -m src.main local.yaml
Ошибка: не удалось получить file:///tmp/none/APKINDEX.tar.gz: ...
```

Граф в тестовом режиме (`examples/config_simple.yaml`, ромб без циклов):

```
$ python -m src.main examples/config_simple.yaml
Граф зависимостей пакета A:
  A -> B, C
  B -> D
  D (нет зависимостей)
  C -> D, E
  E (нет зависимостей)
```

Простой цикл (`examples/config_cycle.yaml`):

```
$ python -m src.main examples/config_cycle.yaml

  A -> B

  C -> A, D

  A -> B -> C -> A

через корень (`examples/config_complex.yaml`). Пакет `X` в файле не
достижим из `A`, поэтому в граф не попадает:

```
$ python -m src.main examples/config_complex.yaml

  F -> F, G
